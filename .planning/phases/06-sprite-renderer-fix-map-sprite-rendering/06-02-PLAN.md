    Edit `GameRenderer.ts`:

    1. In the `render()` method, locate the section where ground tiles are drawn (lines 140-153, around `if (tile.groundId && dat) {` / `drawItem(...)` / `}`).

    2. After the block that draws the ground item (after `this.drawItem(item, screenX, screenY)` on line 143, but BEFORE the fallback `fillStyle` blocks), add minimap color overlay logic:

    ```typescript
    // After drawItem line, add minimap color overlay:
    if (item.minimapColor > 0) {
        const mc = item.minimapColor;
        const mr = ((mc >> 11) & 0x1F) / 31;        // RGB565 red (5 bits)
        const mg = ((mc >> 5) & 0x3F) / 63;          // RGB565 green (6 bits)
        const mb = (mc & 0x1F) / 31;                  // RGB565 blue (5 bits)
        this.ctx!.fillStyle = `rgba(${Math.round(mr * 255)},${Math.round(mg * 255)},${Math.round(mb * 255)},0.25)`;
        this.ctx!.fillRect(screenX, screenY, TILE_SIZE, TILE_SIZE);
    }
    ```

    **Why this location:** The overlay must render AFTER the ground sprite (so it appears on top) but BEFORE the fallback/dark tile styling. This ensures tiles with minimap colors show the tint, while tiles without it remain unchanged.

    **Why RGB565 math:** The minimap color is stored as 5 bits red, 6 bits green, 5 bits blue. To convert to CSS rgba, extract each channel, scale to 0-1 range, then multiply by 255. Alpha of 0.25 gives a visible but subtle tint that doesn't obscure the ground sprite.

    **What NOT to do:**
    - Do NOT modify DatFile.ts (minimapColor parsing is already correct there)
    - Do NOT modify ProtocolGame.ts (minimapColor lookup is done at render time from the item — see Deviations note)
    - Do NOT modify GameMap.ts (existing minimapColor field on TileData is unused, but removing it would break the interface — leave it as-is)

    In `parseTileDescription()` (line 561):
    
    1. Add `const itemIds: number[] = [];` after `let groundId: number | undefined;` (around line 564)

    2. Replace the item capture logic at lines 588-594:
       - BEFORE:

       - AFTER:
         ```typescript
         } else if (result.tibiaId !== undefined) {
             if (groundId === undefined) {

             } else {
                 itemIds.push(result.tibiaId);  // Subsequent things = stacked

         }
         ```

    3. Update the setTile call (line 592-594) to include itemIds:
       - BEFORE:

         ```typescript
         }
         ```
       - AFTER:
         ```typescript
         if (tileX !== undefined) {
             g_gameMap.setTile(tileX, tileY!, tileZ!, {
                 groundId: groundId || undefined,
                 itemIds: itemIds.length > 0 ? itemIds : undefined,
             });
         }
         ```
       Note: The condition changed from `groundId !== undefined &&` to just `tileX !== undefined`. This ensures the tile is created even if there's no ground (edge case). If there's no ground, `groundId` will be `undefined` which is fine — `Object.assign` in setTile won't set it.

    **Part C: Modify GameRenderer.ts — Render stacked items after ground**

    In `render()`, after the ground item drawing block (after the `this.ctx.strokeRect(screenX, screenY, TILE_SIZE, TILE_SIZE)` line at ~153), and before moving to the next tile iteration, add stacked item rendering:

    ```typescript
    // After ground drawing + strokeRect, add stacked items:
    if (tile.itemIds && dat) {
        for (const itemId of tile.itemIds) {
            const stackItem = dat.getItem(itemId);
            if (stackItem) {
                this.drawItem(stackItem, screenX, screenY);
            }
        }
    }
    ```

    **Important notes:**
    - Items render in parse order (server sends ground first, then items in stacking order) — this preserves correct stacking
    - Each item is rendered via `drawItem()` which handles multi-layer, multi-frame sprite layouts
    - Items with no sprite data (fallback) are silently skipped by `drawItem`'s existing `if (!sid) continue` check
    - Do NOT deduplicate itemIds — the server may send multiple of the same item (e.g., multiple coins)
